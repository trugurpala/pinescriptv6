# Repainting taxonomy

Name the mechanism behind a historical/realtime difference: developing-bar values, requested context, intrabar persistence, plotting into the past, strategy execution, alert timing, or dataset revision. An intentional difference can still be useful, but it should be disclosed rather than reduced to a blanket repaint label.

Treat signals derived from a realtime bar's developing high, low, or close as provisional. Confirmation delays the result and changes its timing. The current bar's open and previous-bar values have different stability, while requested timeframes and `varip` require their own analysis.

Local validation can confirm only repository structure and registered claims. It does not prove TradingView runtime equivalence or non-repainting behavior.
